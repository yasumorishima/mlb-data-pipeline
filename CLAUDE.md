## What this is
- `scripts/fetch_*.py` + `.github/workflows/weekly_refresh.yml`: weekly (Mon 01:00 UTC) fetch from Baseball Savant (via `savant-extras`), the MLB Stats API and (frozen) FanGraphs → Parquet → public HF dataset [`yasumorishima/mlb-stats`](https://huggingface.co/datasets/yasumorishima/mlb-stats) (the canonical store; ~19 MB raw + ~2 MB marts). `scripts/check_outputs.py` audits every table; only tables that pass are uploaded.
- `dbt/`: dbt-core + DuckDB marts (contracts enforced on every mart), built by `.github/workflows/dbt_marts.yml` after each refresh and on `dbt/**` changes; published to HF `marts/`; the same SQL is built on a free BigQuery sandbox (`mlb-marts-sandbox`, no billing account) via keyless WIF; `models/bi/` feeds Looker Studio (live, from BigQuery) and Tableau Public (CSV snapshot).
- `analysis/` and `forecast/`: pre-registered decision tests (`PREREG.md` → frozen code md5 → `RESULTS.md`).

## Non-negotiable discipline
1. **Free only (ABSOLUTE).** No paid DWH, BI, LLM API or hosting; nothing that moves to billing automatically. The BigQuery project must stay without a billing account. Never write "it would only cost a few dollars" as an option.
2. **Never publish a table that failed validation.** Keep the order: fetch (each step `!cancelled()`) → audit (`continue-on-error`) → upload only `ok_tables.txt` → a final step turns the run red. Do not make a fetch step `continue-on-error` to get green, do not widen `KNOWN_UNREACHABLE`, do not use `allow_lost_seasons` / `allow_statsapi_shrink` without a measured reason written in the PR.
3. **Contracts stay enforced** on every mart; a type change goes through the contract, not around it. Every new mart gets an independent recomputation test (see `dbt/tests/assert_*_recomputed.sql`) and must pass on both DuckDB and BigQuery.
4. **Pre-register, then run once.** Definitions, thresholds, frozen md5s and the test revision go into `PREREG.md` (and `Amendments`) **before** any outcome is read. Never change frozen code (`analysis/*/pairs.py`, `forecast/team_wins/*.py`, `pred_2026.csv` …) after a result is seen. Readings use the registered words only ("better / worse / indistinguishable"); "indistinguishable" is not "no difference".
5. **Tests must be able to fail.** For every gate or test you add, plant the defect it should catch and show it fails; pin every query parameter, not just the year (Savant silently ignores unknown parameters and returns the current season).
6. Review claims (yours, a sub-agent's, CodeRabbit's) are checked against the code/data before being accepted. Report nulls as facts. No "ceiling / exhausted" framing.
7. No secrets in code, logs or commits (public repo). GCP project id / WIF provider path already in the workflow are public and fine.

## Compute and data access
- `dbt build` runs inside the cloud container: `pip install -r dbt/requirements.txt` (dbt-core 1.12.5 / dbt-duckdb 1.11.0 / duckdb 1.5.5, pinned on purpose), then from `dbt/`: `dbt build --profiles-dir . --vars '{raw_base: "https://huggingface.co/datasets/yasumorishima/mlb-stats/resolve/<sha>"}'` with `<sha>` from `https://huggingface.co/api/datasets/yasumorishima/mlb-stats/revision/main`. ~1 min, reads ~20 MB. The DuckDB file lands in `dbt/target/` (gitignored); do not commit it. `.gitignore` also ignores `*.csv` / `*.parquet`, so a frozen prediction or small result table has to be added with `git add -f` (that is how `forecast/team_wins/*.csv|parquet` got in); never commit raw data. Do not build the `bigquery` target from cloud (no credentials; CI does it via WIF).
- Network needed: `huggingface.co`, **`us.aws.cdn.hf.co`** (parquet `resolve/` URLs 302 there, measured 2026-10-23), **`extensions.duckdb.org`** (DuckDB downloads `httpfs`/`parquet` on first use; the profile loads both), `statsapi.mlb.com`, `baseballsavant.mlb.com`, PyPI. FanGraphs is not needed.
- Secrets (names only, GHA): `HF_TOKEN` (HF write), `DISCORD_WEBHOOK_URL`. BigQuery uses no secret (WIF; provider accepts only `dbt_marts.yml` on `master`).
- BigQuery sandbox storage is 10 GiB for the life of the project and deleting does not give it back; `load_raw_bigquery.py` skips an already-loaded revision — keep it that way.
